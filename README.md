# 受注・納期共有アプリ（体験版）

製造業で、営業が受けた注文を管理部門と工場がすぐ確認し、納期を回答・確定するまでを1か所で共有する業務アプリの**体験版**です。

**体験版（ブラウザで開けます）**：https://updating30.github.io/order-delivery-demo/

## 解決したいこと

| よくある困りごと | このアプリでは |
|---|---|
| 受注が電話・メール・紙で回り、工場が知るのが遅れる | 営業が登録した瞬間に、管理部門と工場の一覧に「まだ見ていない」印つきで出る |
| 納期を誰が回答するのか、もう回答したのかが見えない | 納期を回答するのは工場。1タップで「希望納期でOK」か「この日なら」を返し、営業が確定する |
| 確定した後の前倒しの頼みが口頭で消える | 前倒し・後ろ倒しの依頼と工場の可否が、日付の変化つきの履歴に残る |
| 止まっている案件に気づけない | 「止まって3日以上」「納期まで7日以内」の案件を、急ぎの順に並べて目立たせる |

## 体験版について

- 画面の上の帯で、**営業／管理部門／工場**を切り替え、操作する人を選べます。役割ごとに見える画面と押せるボタンが変わります
- 見本のデータ（架空の顧客12社・品番30・約60件の受注）が、開いた日からの日付で最初から入っています。名前・会社・品番はすべて架空です
- 入れた内容は、そのブラウザの中だけに保存され、どこにも送信されません。帯の「リセット」で見本の状態に戻せます
- 通知のメールや社内チャットは送らず、「こういう文面が届く」という見本だけを表示します

## 試してほしい流れ

1. **すぐ確定**：営業で「受注の登録」→「前回コピー」で数量と希望納期だけ入れて登録 → 工場に切り替えると一覧に印 → 開いて「希望納期でOK」→ 営業に切り替えると通知が届いている
2. **調整して確定**：工場が「要調整」で回答日を入れる → 営業が「この日で確定」。変更履歴に3行残る
3. **確定した後の前倒し**：営業が確定済みの受注で「変更を依頼」→ 工場が「可」→ 確定納期が変わる
4. **溜まりを見つける**：管理部門で「未調整」を開く → 一番上の案件にコメントで工場の担当を呼ぶ → 「運用の数字」で回答までの時間が先週より延びているのを見る

## 作りの特徴

- 入力を増やさない：前回コピー・入力候補・チップで選ぶ入力、入力時間の計測（目標90秒以内）
- 状態の動きは1か所の決まり（遷移の表）だけで決め、表に無い操作は押せないボタンにして理由を出す。どの操作も「元に戻す」が5秒出る
- 運用の数字（確認までの時間・回答までの時間・未調整の件数・変更依頼を受けた割合）は、滞りを見つけるためのもので、人や部門の順位は作らない
- 技術：Next.js・TypeScript・Tailwind CSS。体験版はサーバーもデータベースも使わず、ブラウザだけで動きます
