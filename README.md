# 受注・納期共有アプリ（体験版）

製造業で、営業が受けた注文を管理部門と工場がすぐ確認し、納期を回答・確定するまでを1か所で共有する業務アプリの**体験版**です。

**体験版（ブラウザで開けます）**：https://updating30.github.io/order-delivery-demo/

## 解決したいこと

| よくある困りごと | このアプリでは |
|---|---|
| 受注が電話・メール・紙で回り、工場が知るのが遅れる | 営業が登録した瞬間に、管理部門と工場の一覧に「まだ見ていない」印つきで出る |
| 納期を誰が回答するのか、もう回答したのかが見えない | 納期を回答するのは工場。1タップで「希望納期でOK」か「この日なら」を返し、営業が確定する |
| 確定した後の前倒しの頼みが口頭で消える | 前倒し・後ろ倒しの依頼と工場の可否が、日付の変化つきの履歴に残る |
| 止まっている案件に気づけない | 「止まって3日以上」「納期まで7日以内」の案件を、急ぎの順に並べて目立たせる |
| 工場のどの日に余裕があるか見えないまま、納期を回答している | 納期の日ごとの工数（品番の1個あたりの工数×数量）をグラフに出し、上限を超える日を赤くする。回答の日を選ぶボタンにも、その日の混み具合が出る |

## 体験版について

- 画面は3つのタブです：① 受注を入れる／② 受注ボード（4つの数字・工場の負荷・あなたの対応待ちのカード・受注の一覧）／③ 負荷と履歴
- 画面の右上の「利用者」で、**営業／管理部門／工場**の人を選べます（人を選ぶと部門も決まります）。部門ごとに、対応待ちのカードと押せるボタンが変わります
- 見本のデータ（架空の顧客12社・品番30・約60件の受注）が、開いた日からの日付で最初から入っています。名前・会社・品番はすべて架空です
- 入れた内容は、そのブラウザの中だけに保存され、どこにも送信されません。画面の下の「デモデータに戻す」で見本の状態に戻せます
- 通知のメールや社内チャットは送らず、「こういう文面が届く」という見本だけを表示します

## 試してほしい流れ

1. **すぐ確定**：営業（佐倉 拓海）で「① 受注を入れる」→「前回コピー」で数量と希望納期だけ選んで「1タップで登録」→ 利用者を工場の人（大槻 誠）にすると、受注ボードの一覧に「まだ見ていない」印 → 開いて「希望納期でOK」→ 営業に戻すと、右上の通知（ベル）に届いている
2. **調整して確定**：工場が受注ボードのカードで「要調整：回答日を入れる」（日付のボタンに、その日の工場の負荷が出ます）→ 営業の受注ボードに「調整案が届いています」のカード →「この日で進める」。変更履歴に3行残る
3. **確定した後の前倒し**：営業が確定済みの受注を開いて「変更を依頼」→ 工場の受注ボードの「前倒し・延期の依頼中」から開いて「可」→ 確定納期が変わる
4. **溜まりを見つける**：管理部門（高森 由佳）の受注ボードで「未調整（急ぎの順）」の一番上を開く → コメントで工場の担当を呼ぶ →「③ 負荷と履歴」の「運用の数字」で、回答までの時間が先週より延びているのを見る

## 作りの特徴

- 入力を増やさない：前回コピー・入力候補・チップで選ぶ入力、入力時間の計測（目標90秒以内）。工場の負荷は、品番ごとの1個あたりの工数×数量で自動で出すので、営業・工場が入れるものは増えない
- 状態の動きは1か所の決まり（遷移の表）だけで決め、表に無い操作は押せないボタンにして理由を出す。どの操作も「元に戻す」が5秒出る
- 運用の数字（確認までの時間・回答までの時間・未調整の件数・変更依頼を受けた割合）は、滞りを見つけるためのもので、人や部門の順位は作らない
- 技術：Next.js・TypeScript・Tailwind CSS。体験版はサーバーもデータベースも使わず、ブラウザだけで動きます
